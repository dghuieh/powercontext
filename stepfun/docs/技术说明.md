# 一页技术说明：StepFun × seekdb 端侧迷你知识库

## 1. 模型与量化

| 项 | 内容 |
| --- | --- |
| 模型 | `sentence-transformers/all-MiniLM-L6-v2`（Apache-2.0，384 维），权重来源：魔搭镜像 `AI-ModelScope/all-MiniLM-L6-v2`，版本 commit `ec79a486` |
| 运行时 | Transformers.js 3.0.2 + ONNX Runtime Web |
| 量化方式 | onnxruntime `quantize_dynamic(weight_type=QuantType.QUInt8)`，对 MatMul/Gemm 权重做动态 INT8 量化，激活在线量化 |
| 量化前体积 | 86.2 MB（`onnx/model.onnx`） |
| 量化后体积 | 21.8 MB（`onnx/model_quantized.onnx`） |
| 压缩比 | **3.95×** |

**检索质量变化**（8 段中英文文档 × 4 条查询，归一化后取余弦）：

- FP32 与 INT8 的文档向量逐条余弦：0.9905 / 0.9867 / 0.9914 / 0.9869 / 0.9911 / 0.9855 / 0.9908 / 0.9873，**均值 0.9888**
- 4 条查询的 Top-1 结果与 FP32 完全一致（`top1_same=true`），Top-3 顺序有 1 条查询的第 2、3 名互换（`top3_same=false`）

结论：INT8 在体积压缩到 1/4 的同时，向量空间几乎不变，实际检索命中在 Top-1 层面无损。

## 2. 端侧运行

- **推理位置**：文档向量化与查询向量化均在浏览器内执行；后端服务仅有 `/api/ingest`、`/api/search` 两个数据接口，代码中不加载任何模型，也不存在任何云端推理请求。
- **后端选择**：`app.js` 先探测 `navigator.gpu`，有则 `pipeline(..., {device:'webgpu', dtype:'q8'})`；初始化抛错则回退 `device:'wasm'`。当前后端写入页面右上角徽标（`WebGPU（INT8）` / `WASM（INT8）`），不会静默切换。
- **降级验证方法**：Chrome/Edge 启动参数 `--disable-features=WebGPU` 或在 `chrome://flags` 关闭 WebGPU，刷新后徽标应显示 `WASM（INT8）`，导入与检索流程仍完整可用。
- **模型本地化**：`env.allowRemoteModels=false`、`env.localModelPath='/models/'`，模型从应用自身静态目录加载，不走公网；首次加载为冷启动，之后命中 HTTP 缓存。

## 3. seekdb 使用

**表结构**（`server/schema.sql`，由 `seekdb-js.createCollection()` 自动创建）

| 列 | 类型 | 用途 |
| --- | --- | --- |
| doc_id / chunk_id | VARCHAR(128) / INT | 联合主键，保证增量导入幂等 |
| title / content | VARCHAR(512) / MEDIUMTEXT | 原文与展示标题 |
| meta | JSON | 来源、批次等元数据 |
| embedding | VECTOR(384) | 端侧生成的向量 |
| created_at | BIGINT | 写入时间，用于会话/批次管理 |

**索引**：`CREATE VECTOR INDEX ... WITH (type=HNSW, distance=cosine)`；`CREATE FULLTEXT INDEX ... (content)`。若目标版本未开启全文索引能力，自动退化为库内 `LIKE` 打分（仍是库内计算），检索响应中的 `mode` 字段暴露实际模式。

**混合检索在库内完成**：一条 SQL 同时算出 `vec_score = 1 - COSINE_DISTANCE(embedding, :q)` 与 `txt_score`（`MATCH ... AGAINST`），再按 `α·vec + (1-α)·txt` 排序并 `LIMIT`。前端只拿到已排序结果，**不做两路召回结果在客户端的拼合**。

```sql
SELECT doc_id, chunk_id, title, content,
       ROUND(1 - COSINE_DISTANCE(embedding, :q), 6) AS vec_score,
       ROUND(MATCH(content) AGAINST (:qtext), 6) AS txt_score,
       ROUND(0.7 * (1 - COSINE_DISTANCE(embedding, :q)) + 0.3 * MATCH(content) AGAINST (:qtext), 6) AS score
FROM kb_default ORDER BY score DESC LIMIT 8;
```

**增量写入与刷新**：`INSERT ... ON DUPLICATE KEY UPDATE` 按 `(doc_id, chunk_id)` 覆盖写，重复导入不产生重复向量；写入完成后即建索引查询，新文档可立即检索（HNSW 增量插入）。集合名由界面传入，`kb_a` / `kb_b` 互不影响，切换集合后检索结果与当前知识库严格一致。

## 4. 状态管理与优化

- **集合与会话状态**：集合名 + 数据库当前行数（`total_rows`）随每次导入回显，避免「以为写进了 A 库其实在 B 库」。
- **批处理**：前端按 `BATCH=8` 分批送入模型，进度条按批推进，避免一次性喂入长文本造成显存/内存尖峰。
- **模型加载**：单例加载一次，查询与导入复用同一 pipeline 实例，避免重复初始化。
- **索引策略**：索引在写入前创建，写入走批量 upsert，不做全量重建。
- **计时口径**：分阶段记录「模型下载/加载 → 文档向量化（含预热 / 预热后）→ 写入 seekdb → 查询向量化 → seekdb 检索 → 端到端」，界面第 3 屏展示中位数与样本数 n，不只取最快一次。

## 5. 复现与限制

- 复现：`docker run -d -p 2881:2881 oceanbase/seekdb:latest` → `cd stepfun && npm install && npm start` → 打开 `http://127.0.0.1:8787`。
- 本机开发环境（Windows 11 / i5-13420H / Intel UHD）上 `seekdb.exe` 因运行时 DLL 缺失无法启动（`STATUS_0xC0000135`），因此数据库链路的可运行性以 docker 镜像方式提供；应用在 seekdb 不可用时明确返回 503，不会退化到内存检索伪装成成功。
- 上表量化一致性数据由 `tools/quantize_int8.py` + `benchmark/` 同模型在 CPU 实测得到（4 线程），浏览器 WebGPU/WASM 的分阶段延迟需在目标机器按界面计时表重测。
